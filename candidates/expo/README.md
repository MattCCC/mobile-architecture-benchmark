# Candidate `expo`: React Native with Expo

## Architecture

React Native app built with the Expo SDK and Continuous Native Generation: `android/` and `ios/` are generated by
`npx expo prebuild --clean` on every build and never edited by hand; all native settings live in `app.json` and the
config plugin `plugins/withMobileBench.js`. Navigation is an expo-router Stack (file routes in `app/`), the UI is the
shared RN UI in `../_rn-shared/ui` (List with `FlatList`, Selection, Detail with an `Animated` panel on the native
driver, Insights embedded, Error), and instrumentation is the shared BenchKit wrapper `../_rn-shared/rn-benchkit`
(linked as `@mobilebench/rn-benchkit`, autolinked by Expo). The update stream is replayed in-app from the bundled
deterministic stream by default; `mb.source=websocket` switches to the local server (see `../_rn-shared/README.md`).

Routes: `app/index.tsx` (List, header hidden; the screen draws the normative bands itself), `app/selection.tsx`,
`app/detail/[i].tsx`, `app/insights.tsx`; `app/_layout.tsx` boots the session, reports route changes at transition
start (`navSeq`) and rebuilds a restored stack.

## Build commands

From the repository root (the root Makefile includes `candidates/*/candidate.mk`):

| Target | Does |
|---|---|
| `make deps-expo` | `npm ci` from the committed lockfile |
| `make check-expo` | verified assets, shared unit tests, pins/registry check, `tsc`, ESLint (app + shared), `npx expo install --check` |
| `make build-expo-android` | `scripts/build-android.sh`: assets → local key → `npx expo prebuild --clean --platform android` → `./gradlew :app:assembleRelease` → `build/android/app-arm64-release.apk` |
| `make build-expo-ios` | `scripts/build-ios.sh`: assets → prebuild → `pod install` → `xcodebuild` Release, iOS simulator arm64, unsigned → `build/ios/MBExpo.app` |
| `make clean-expo` | removes generated native projects, build outputs and assets |
| `make artifacts-expo-android` / `-ios` | print artifact paths |

Android builds need JDK 17 and the Android SDK (`../_rn-shared/tools/android-env.sh` resolves `MB_JAVA_HOME`,
`JAVA_HOME`, `/usr/libexec/java_home -v 17`, Homebrew `openjdk@17`; `ANDROID_HOME`). Release builds are signed with
a local non-distribution key from `MB_KEYSTORE_PROPERTIES` (default `../_rn-shared/.keys/`, created on first build,
gitignored). Device builds for iOS need your own team and bundle id; they are not scripted.

Run (functional use): `adb shell am start -n org.example.mobilebench.expo/.MainActivity --es mb.profile representative`
or `xcrun simctl launch <udid> org.example.mobilebench.expo -mb.profile representative`. Launch keys: design §6.5
plus PoC keys `mb.source` (`replay` | `websocket`) and `mb.count` (replay end after n messages).

## Release settings

Android: R8 minify and resource shrinking (`expo-build-properties`), Hermes V1 bytecode, arm64-v8a only
(`buildArchs`), `androidx.profileinstaller:profileinstaller:1.4.1`, `<profileable android:shell="true"/>`, cleartext
only for `localhost`, `127.0.0.1`, `10.0.2.2` (network security config), light theme (`userInterfaceStyle` +
expo-system-ui). iOS: Release, deployment target 16.4, iPhone only, `CADisableMinimumFrameDurationOnPhone`,
`NSAllowsLocalNetworking`, `NSLocalNetworkUsageDescription`, `UIUserInterfaceStyle = Light`. No splash module is
installed: only the platform launch screen is used (the Expo template's launch theme `Theme.App.SplashScreen` is
replaced by `AppTheme` before the first frame).

(pilot-validate); `contentLayerPattern` in candidate.json. iOS: UIKit views; `XCTOSSignpostMetric` expected valid,
`XCTHitchMetric` pilot. Markers: see `../_rn-shared/README.md`.
